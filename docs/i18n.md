# Interface languages

The launcher speaks English, Simplified Chinese, Traditional Chinese, Japanese, Korean,
German, French and Spanish. This file is the contract for adding copy, adding a language,
and the checks that keep the catalogs and the readmes honest.

## Where the copy lives

| File | Role |
|---|---|
| `src/i18n/en.ts` | The source. Every key exists here, and every value is a literal so the `{placeholder}` set can be read off the type. |
| `src/i18n/zh-Hans.ts` | Simplified Chinese. Partial: a key that is missing reads in English instead of blank. |
| `src/i18n/zh-Hant.ts` | Traditional Chinese (Taiwan wording). Partial, same fallback. |
| `src/i18n/<tag>.ts` | One file per further language (`ja`, `ko`, `de`, `es`, `fr`), same shape and same fallback. |
| `src/i18n/languages.ts` | One row per language: the endonym the selector shows, the `Intl` date tag, the list separator, and the collator locale. Everything that varies by language and is not a sentence lives here. |
| `src/issue-messages.json` | One entry per `Issue.code`, keyed by language tag. Rust emits the code; the UI owns the sentence. A language without a translation reads in English. |
| `shared/labels.json` | The few strings Rust renders itself: the tray menu and generated configuration names. Rust reads it with `include_str!`, the frontend imports the same file, so there is one template rather than two copies. |
| `src/i18n/coverage-baseline.json` | How many keys each language had when coverage was last accepted, as a count, not a percentage. |

## Key rules

- Keys are `<feature>.<element>`, e.g. `session.chainThinCfg`. The feature groups the
  catalogue into `app`, `nav`, `settings`, `quit`, `notice`, `dialog`, `common`, `form`,
  `project`, `profile`, `configChoice`, `configurations`, `config`, `sessions`, `session`,
  `about`.
- A key is written once, in `en.ts`, and independently translated. Nothing is
  concatenated at runtime to build a sentence: word order differs between the languages,
  so a whole sentence is one value.
- Placeholders are `{name}`. A translation must declare exactly the same placeholder set
  as the source; the catalog test compares the two and names the key when they differ.
  A missing value renders as an empty string at run time, which is why the test exists —
  the compile-time check only covers the English literal.
- Numbers, dates, lists and language names go through `Intl` (`NumberFormat`,
  `DateTimeFormat`, `PluralRules`, `DisplayNames`, `Collator`). The per-language inputs are
  in `languageProfiles`; nothing else hard-codes a locale.
- A sentence whose noun agrees with a count carries `.one` and `.other` variants
  (`config.usedByProjects.one`), and the call site asks `pluralKey(language, base, count)`
  for the variant. The category comes from `Intl.PluralRules`, not from `count === 1`:
  Chinese and Japanese select `other` for every number, so both variants there hold the
  same sentence. A language whose plural rules need `few`/`many` (Russian, Polish) would
  need more variants; none of the eight does.
- `Intl.ListFormat` is deliberately not used for the compact label joins
  (`界面设置、环境设置`): CLDR gives the Chinese unit pattern no separator at all, and its
  conjunction pattern inserts 和/及. `joinList` keeps one explicit separator per language.
- The language selector names each language in its own words (`简体中文`, `日本語`,
  `Deutsch`), because a reader looking for their language recognises it by that name, not
  by a translation. The endonym is data in `languageProfiles`, not a message key, and each
  `<option>` carries a `lang` attribute.

## Adding a key

1. Add the English value to `src/i18n/en.ts`.
2. Add the value to every other catalogue (the fallback makes this optional, but an
   untranslated key shows as English in that language).
3. `npm run test` — the catalog test fails if the key is unknown, unused, empty, or has a
   different placeholder set; the coverage guard fails if a language dropped a key.
4. `npm run i18n:coverage` prints the table and the missing keys. `--update` rewrites the
   baseline, which is the deliberate way to accept a drop; do that in its own commit.

## Adding a language

1. `src/i18n/<tag>.ts`, exporting `messages: Partial<Record<MessageKey, string>>`.
2. Add the tag to the `Language` union in `src/api.ts`, a row to `languageProfiles` in
   `src/i18n/languages.ts` (endonym, date tag, list separator, collator locale), and the
   import to `catalogs` in `src/i18n/index.ts`. The endonym is also what the selector shows.
3. Add the language to every entry of `src/issue-messages.json`; the catalog test asserts
   each code is written in every interface language. Do the same for `shared/labels.json`.
4. Rust: add a `LanguagePreference` variant, its `resolve` arm and an `is_<language>` guard in
   `src-tauri/src/language.rs`, and extend `LANGUAGES` in `src-tauri/src/labels.rs`. The
   system mapping matches the primary subtag (`ja-JP` → `ja`) and falls back to English.
5. Add the option to the language selector in `src/pages/Settings.tsx`, after the existing
   languages by tag, with its own `lang` attribute so the browser picks the right glyphs and
   the screen reader the right voice.
6. The installer must already offer that language: `src/lib/installer.test.ts` asserts every
   interface language has an NSIS name in `bundle.windows.nsis.languages`.
7. Record the baseline with `npm run i18n:coverage -- --update`.

## Checks in the suite

- `src/i18n.test.ts` — the English source and the catalogs interpolate.
- `src/i18n/catalog.test.ts` — unknown keys, placeholder drift, empty strings, unused
  keys, lost coverage, and issue copy in every interface language.
- `src/i18n/languages.test.ts` — one profile per interface language, its endonym matching
  `Intl.DisplayNames`, and its date and collator locales accepted by `Intl`.
- `src-tauri` `every_issue_code_used_in_rust_exists_in_issue_messages` — both directions:
  every code the backend hands out has copy, and every entry in `src/issue-messages.json`
  is still mentioned somewhere in `src-tauri/src`. This asserts; it used to print a warning.
- Page tests render in every language the UI can show, so the source language is exercised
  through the UI rather than only through the catalogue.
- `src/lib/installer.test.ts` — the installer only offers NSIS languages Tauri translates,
  every interface language has one, and the install hook carries copy for the languages it
  offers without using `LangString`.
- `scripts/readme-languages.test.mjs` — the eight readmes keep one structure; see below.

## Readmes

`README.md` is the English original and `README.zh-CN.md`, `README.zh-Hant.md`,
`README.ja.md`, `README.ko.md`, `README.de.md`, `README.fr.md`, `README.es.md` are the
translations. Prose is translated; commands, paths, key names, URLs, version numbers and
licence names stay as they are, and the `sas` code block is identical everywhere. The
screenshots are shared and the caption says so: they show the Simplified Chinese interface.

The switcher under the badge row lists all eight in one order and bolds the current one
without linking it. `scripts/readme-languages.test.mjs` compares each translation with
`README.md`: the same number of H2 and H3 headings, the same code blocks byte for byte, a
switcher with eight entries and exactly one current language, and relative links that
resolve to files that exist. The prose is free to differ; the skeleton is not.

## Backend labels

`shared/labels.json` holds the copy for what the backend prints itself:
`tray.showWindow`, `tray.quit`, `config.defaultBaseLabel`, and the generated-name
template `config.derivedName` (`… {base} … #{index}`). Each entry is keyed by language, and
a missing translation falls back to English. `src-tauri/src/labels.rs` parses it once and
fills the placeholders; `src/lib/config.ts` imports the same file. An unknown key renders as
the key itself, and a Rust test scans `src-tauri/src` for `"config.`/`"tray.` literals so a
missing entry fails the suite instead of reaching the UI.

A generated configuration name is numbered per source across every language: a name
written under English still occupies `#1`, so switching the interface language cannot
produce two `#1`s for the same source.

## Pseudo locale

`?pseudo=1` in a development build renders every message as `[[key | args]]`, so a string
that was never translated, or one that outgrows its button, is visible without reading the
catalogs. It is not reachable in a packaged build and is not offered in Settings.

## Installer

`bundle.windows.nsis` lists the 23 NSIS languages Tauri 2 ships copy for, English first
because the first entry is the fallback, with `displayLanguageSelector` on. The selector
pre-selects the detected language and remembers the choice in
`HKCU\\Software\\<manufacturer>\\<product>\\Installer Language`; a later install reuses it
instead of asking again.

The installer language is independent of the app language: the app still follows its own
`System` preference on first launch.

Two rules for `src-tauri/windows/preserve-install-location.nsh`:

- **`LangString` is not usable here.** `makensis` answers `command LangString not valid in
  Section` because the Tauri template expands hook macros inside a Section, and a top-level
  `LangString` in the hook would be read before the language table is loaded. The hook takes
  its copy from `$LANGUAGE` at run time instead, with English as the fallback.
- The file must stay UTF-8 **without a BOM**: `makensis` runs with `-INPUTCHARSET UTF8`.
  The guard test fails on a BOM.
- `${MANUPRODUCTKEY}` is only valid inside the hook macro, because the template defines it
  after the `!include`.

Do not add a language Tauri has no translation for (2.12.6 ships 23). The build stays
green and the installer then shows raw `$(createDesktop)`-style strings.

## Known limits

- Changing the Windows display language needs a sign-out, so the app resolves the system
  language once at startup and a restart is what picks it up. Tauri 2 has no locale-change
  event (`WindowEvent` has none), and hooking `WM_SETTINGCHANGE` would cost window-subclass
  risk for a case Windows already makes rare.
- The installer's language is not fed back into the app; see above.
- A configuration keeps the name it was created with. Renaming on a language switch would
  edit user data behind the user's back, so a name written under German stays German.
