## <a id="zh"></a>简体中文

安装包：`SAS-Launcher-0.4.0-x64-Setup.exe`

### 安装

1. 升级前先退出正在运行的启动器，并关掉所有 SAS 会话——保存用户设置要独占读写 `My SAS Files`，SAS 开着会让保存失败。
2. 运行安装包，沿用原来的安装位置直接覆盖升级，不需要先卸载；安装向导可用 23 种语言中的任意一种，选择会被记住。
3. 项目、配置与会话记录留在 `%LOCALAPPDATA%\com.saslauncher.desktop\v4`，安装包不会清空它们。

回退：重装 v0.3.0 的安装包即可；0.4.0 写入的 `v4` 数据旧版仍能读取，只会忽略新增的启动文件字段。

### 新增

- 让项目在启动时先执行自己的 autoexec 文件：路径在项目里设置，缺失或相对路径在保存和启动时都会被拒绝。
- 脚本需要从自身位置推导项目路径时，打开「向会话提供启动文件路径」，会话里就能用 `&SASLAUNCHER_STARTUP_FILE` 拿到它。
- 还在读 `SAS_EXECFILEPATH` 的旧启动脚本可以一键「迁移启动文件」：只改写认得的赋值，原文件保留为 `.bak`，改完自动重开。
- 在项目列表里标出正在运行的项目，按钮直接禁用，不必等点击之后的报错。
- 新增「关于」页：版本、构建提交、可粘贴的版本信息、源码仓库与问题反馈入口都集中在这里。
- 在「关于」页点「检查更新」会查询 GitHub Releases，并说明拿到的是正式版还是预发布版。
- 界面新增繁体中文；英文、简体中文、繁体中文三套文案都完整，不再回退到英文。
- 安装程序提供 23 种语言的选择器，默认跟随系统，并记住上次选择。
- 托盘菜单和自动生成的配置名跟随界面语言，不再固定中文。
- 选择「跟随系统」时，设置页会显示实际解析到的语言。

### 优化

- 配置列表按当前界面语言排序：中文按拼音，英文按字母。
- 语言名称改用各自的语言书写（简体中文、繁體中文、English），不再被界面语言翻译。
- 数量文案按各语言的复数规则显示，不再出现 `1 project(s)`。
- README 的版本徽章在预发布阶段也能显示最新版本。
- 项目行的操作按钮固定在右侧一列，长项目名不再把它们挤走。
- 卡片里的提示改成横条，少一层套框。

### 修复

- 命令 panic 后不再需要重启应用：恢复共享状态，并说明项目与启动脚本没有受影响。
- 启动文件按字符而不是字节扫描，含中文等非 ASCII 内容的行不再被误判。
- 启动失败只标在对应项目行，不再串到别的项目。
- GBK 编码的启动脚本也能迁移：按字节改写，保留原编码与中文路径。
- 安装程序拒绝把已登记的安装移动到新目录，避免留下旧文件、卸载项指向新位置。
- 安装钩子的提示按运行时语言显示，英文与繁体中文安装不再读到中文句子。

### 其他改动

- 发布正文改由仓库里的 `docs/release-notes/v<version>.md` 提供，不再依赖自动生成的 PR 列表。
- 发布前的版本 guard 现在同时核对 `package-lock.json` 与 `Cargo.lock`，CI 每次推送都会跑。
- `package-lock.json` 的版本字段与三个清单保持一致。
- i18n 拆成每语言一份 catalog、英文为源、消息键按功能命名，并新增覆盖率、未知键与漂移检查。
- 测试补齐英文页面、启动扫描与安装器语言守卫；文档记录语言契约、CJK 排版与启动文件迁移的适用范围。
- 发布说明模板去掉每条上限，改为四段式；三个新文本文件统一为 CRLF。

### 已知限制

- 迁移只认得读 `SAS_EXECFILEPATH` 的几种写法；其它写法会拒绝迁移，需要手工改。
- 安装程序的语言选择只影响安装过程，不会写回应用语言。
- 更改 Windows 显示语言后，应用要重启才会解析到新语言。
- 检查更新走 GitHub 的匿名接口，网络不通或请求过多时会直接说明原因。

## <a id="english"></a>English

Installer: `SAS-Launcher-0.4.0-x64-Setup.exe`

### Install

1. Quit the launcher and close every SAS session first: saving user settings needs exclusive access to `My SAS Files`, and a running SAS blocks it.
2. Run the installer over the existing folder; it upgrades in place, with no uninstall step. The wizard offers any of 23 languages and remembers the choice.
3. Projects, configurations and session logs stay in `%LOCALAPPDATA%\com.saslauncher.desktop\v4`; the installer never clears them.

Rolling back: reinstall the v0.3.0 installer; the `v4` data written by 0.4.0 still reads there, which only ignores the new startup-file fields.

### Added

- Run a project's own autoexec file at launch: the path is set on the project, and a missing or relative path is refused when saving and when launching.
- Hand the startup file's path to the session with "Tell the session where the startup file is", readable as `&SASLAUNCHER_STARTUP_FILE` when a script derives its paths from its own location.
- Migrate a startup script that still reads `SAS_EXECFILEPATH`: only the known assignment is rewritten, the original stays as `.bak`, and the launch retries.
- Mark a running project in the list and disable its button, instead of waiting for the error after the click.
- An About page now names the version and the build commit, copies one pasteable version line, and links the repository and the issue tracker.
- "Check for updates" asks GitHub Releases for the newest release and says whether it is a pre-release.
- Traditional Chinese joins the interface: all three languages carry a complete catalog and never fall back to English.
- The installer offers 23 languages in a selector, follows the system by default and remembers the choice.
- The tray menu and generated configuration names follow the interface language instead of staying Chinese.
- "Follow System" now shows the language it resolves to under the selector.

### Improved

- Configuration lists sort by the interface language: pinyin for Chinese, alphabetical order for English.
- Language names are written in their own words (简体中文, 繁體中文, English) instead of being translated.
- Counted sentences follow each language's plural rules, so `1 project(s)` is gone.
- The README release badge shows the newest release while releases are pre-releases.
- A project row keeps its action buttons in a fixed column, so a long name no longer pushes them around.
- A notice inside a card is a band instead of a box inside a box.

### Fixed

- A panicking command no longer requires a restart: the shared state is recovered, and the message says projects and startup scripts are untouched.
- Startup files are scanned by character, not byte, so lines with Chinese or other non-ASCII text are no longer misread.
- A failed launch stays on the project row it belongs to.
- A GBK startup script migrates too: the rewrite works on bytes and keeps the original encoding and Chinese paths.
- The installer refuses to move an installation the registry already knows, so no old files are left behind and the uninstall entry does not move.
- The install hook picks its sentence from the runtime language, so English and traditional Chinese installs no longer read a Chinese one.

### Other changes

- The release body now comes from `docs/release-notes/v<version>.md` instead of `--generate-notes`.
- The version guard also checks `package-lock.json` and `Cargo.lock`, and CI runs it on every push.
- The `package-lock.json` version fields stay in step with the three manifests.
- i18n moved to one catalog per language, with English as the source and feature-named keys, plus coverage, unknown-key and drift checks.
- Tests cover the English pages, the startup scan and the installer language guard; docs record the language contract, CJK typography and where the startup migration applies.
- The release-notes template drops its per-section caps for four sections, and the three newest text files are stored with CRLF.

### Known limitations

- The migration only recognises the `SAS_EXECFILEPATH` shapes it knows; anything else is refused and needs a manual edit.
- The installer's language choice only affects the installation, not the app language.
- After a Windows display-language change the app has to restart before it resolves the new language.
- The update check uses GitHub's anonymous API; it says so when the network fails or the quota is exhausted.

> [!IMPORTANT]
> This installer is unsigned. Windows SmartScreen will warn when you run it: choose "More info" and then "Run anyway" only if you trust this build.

The full commit list is at the end.
